# Docs

| File | What it is for |
|---|---|
| [RUNBOOK.md](RUNBOOK.md) | Every operational procedure, grouped by system under a table of contents, each with When / Status / Dry run / Apply / Verify / Rollback; the form ids and links; the live gate; the automatic sync's switches |
| [ARCHITECTURE.md](ARCHITECTURE.md) | The flow sheet → Roster → Jotform → Salesforce with file:function pointers; constants that exist on both sides; parity bridges; known divergences; privacy boundaries |
| [DECISIONS.md](DECISIONS.md) | One section per decision that shaped the system, in date order, with why and what was rejected |
| [BACKLOG.md](BACKLOG.md) | What remains, one section per item with its status; finished and dropped items at the end |
| [SHEETS-ACCESS.md](SHEETS-ACCESS.md) | Giving the tooling (and CI) service-account access to the master enrollment sheet |
| [plans/](plans/) | One plan per change with a live rollout, beside its ticket, `YYYY-MM-DD-slug.md`, with its Result once done (and, for a finished one-time procedure, the RUNBOOK's former text). [plans/README.md](plans/README.md) is the index, generated by `make docs-index` |
| [intent/](intent/) | Ryan's ask, captured before a plan exists (optional) |
| [templates/](templates/) | The plan and intent templates |
| [agent/](agent/) | Handoff notes between Claude sessions: [agent/handoff.md](agent/handoff.md), written by `/harness:handoff` before context is cleared and read at the next session's start |
| [archive/](archive/) | Historical documents kept for the reasoning: the original 2026-08-24 plan, the 2026-09-01 launch notes, the one spec (the spec stage is retired), the offline roster rebuild |
| [screenshots/](screenshots/) | Images the plans refer to |

How work flows (the AI-native SDLC playbook, adapted): work is a ticket on the board, an epic
with its task sub-issues. `/harness:plan` turns a request into tickets; `/harness:work` does a
ticket tests first (a red proof before any code), then review, then a pull request on a
`t/<issue>-<slug>` branch; `/harness:land` squash-merges it after `/land-checks`. A **plan** under
`plans/` is kept only beside a ticket whose change has a live rollout (Rollout, Rollback,
Result); it gets its status and `done:` date, and `make docs-index` updates the index. An
**intent** stays optional: it only captures Ryan's ask before a plan exists. A choice a future
reader would re-litigate goes into DECISIONS; BACKLOG items keep their numbers and get dated
bullets, and new work is a ticket. A change is reviewed against
[../REVIEW.md](../REVIEW.md): every line of the ticket's Definition of done holds and
`scripts/verify.sh` (`make check`, then `VERIFY OK`) passes. `CLAUDE.md` at the root is the one-page institutional memory for Claude.
