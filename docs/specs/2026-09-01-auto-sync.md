# Spec: automatic Jotform sync

## Summary

The sheet's Apps Script sends a GitHub `repository_dispatch` event whenever the Roster changes.
A workflow runs `tools/auto_sync.py`, which exports the Roster, plans the sync per region with
the existing tool, applies only inside safety bands, verifies, and appends one row per region
to a `SyncLog` tab in the sheet. A daily scheduled run is the backstop.

## Behaviour

1. `handleNewClub_`, `handleRosterChange_`, `rebuildRosterFromResponses` and
   `refreshRosterRegions` call `tryNotifySync_(reason)` after their Audit row, only when they
   changed the Roster; a failure is logged to the Audit tab and never fails the submission.
2. `notifySync_` returns without doing anything unless Script Properties `SYNC_DISPATCH_REPO`
   and `SYNC_DISPATCH_TOKEN` are both set; it writes `syncRequested <reason> → HTTP <code>`.
3. The workflow runs on `repository_dispatch` (`roster-changed`), on a daily schedule (the cron
   is UTC — 06:00 Chicago in summer, 05:00 in winter), and by hand; one run at a time, at most
   one more pending (a burst beyond that is coalesced — every run syncs the whole Roster, so
   nothing is lost).
4. The runner exports the Roster tab in-process (retry with backoff), refuses an export with
   fewer than 1,000 active rows, and reports active girls with a blank region as ATTENTION.
5. Per region: dry run → no CREATE/UPDATE/DELETE (a picker option change counts) → `in-sync`;
   else bands: ≤ 5 creates, ≤ 20 updates, 0 deletes, no "shares NO names" warning, not a
   truncated export → else `attention`, nothing written.
6. With `--apply` and inside the bands: `backup_forms.py --form` → `sync --apply` (one retry) →
   `form_status.py --json` must show 0 error conditions, Salesforce present, ≥ 12 languages, no
   club missing from the form, no roster out of date → `applied`; problems found →
   `applied-with-problems`; the verification itself could not run → `applied-unverified`
   (raises ATTENTION — a live write must never pass unchecked); the write failed → `failed`.
7. With `--synclog` (the workflow always passes it; a local run without it writes nothing to
   the sheet) every region's outcome is appended to `SyncLog` (`when, trigger, region, mode,
   creates, updates, rules, result, detail, run_url`); the console output is redacted as it is
   produced, and the log plus `ATTENTION.md` under `data/auto_sync/` are kept as workflow
   artifacts together with the conditions-only rollback files
   (`backups/<form>/conditions-<stamp>.json`) — never the full properties snapshots or any
   roster.
8. Exit 0 all in sync or applied; 2 attention; 1 failed — so the workflow fails visibly.
9. Writes happen only when the repository variable `AUTO_SYNC_APPLY` is `1` (and, for a manual
   run, the "apply" input is ticked).

## Interfaces

`tools/auto_sync.py [--apply] [--synclog] [--region R]* [--trigger NAME] [--roster CSV]
[--max-creates 5] [--max-updates 20] [--min-active 1000] [--out DIR] [--run-url URL]`;
`sync_attendance_form.py --summary-json PATH`; Script Properties above; secrets
`JOTFORM_API_KEY`, `GLOW_SA_JSON`, `GLOW_SHEET_ID`; variable `AUTO_SYNC_APPLY`; menu item
**GLOW → Google Forms → Request Jotform sync now**.

## Policies applied

`jotform-api` (the sync rewrites all conditions each run — the runner gates on the plan, not on
the rewrite), `child-privacy` (redaction, artifact allow-list), `live-systems` (backup, verify,
bands, kill switch).

## Out of scope

A native Apps Script port of the sync (old backlog 7–9); the parity harness between Python and
Apps Script dry runs (10); requiring a ticked girl on the forms.

## Acceptance

`make check` green (runner logic unit-tested); `python3 tools/auto_sync.py` with the
key loaded prints `in-sync` for every region; after Ryan's setup: an Audit row
`syncRequested manual → HTTP 204`, a green dry-run workflow, a `SyncLog` row per region; after
`AUTO_SYNC_APPLY=1`: a real roster change shows `applied` and `form_status` stays CLEAN.
