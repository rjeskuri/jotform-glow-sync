# Plan: a work log for invoicing (hours per day + what was done)


## Context
Ryan bills this work to the client monthly. He needs a file he can export at month end:
each day's hours and a description of the work. Claude Code's session transcripts
(`~/.claude/projects/-Users-ryaneskuri-jotform-glow-sync/*.jsonl`) timestamp every message, so
hours can be *reconstructed*, not remembered. They are deleted after 30 days by default, so the
log must capture them regularly. Ryan's choices (2026-09-28): the log is committed in the repo;
hours = active time with 30-minute gaps, rounded to the quarter hour per day; back-fill
September only.

## Design
**`tools/worklog.py`** (standard library only; argparse; `print()`):
- `update [--since 2026-09-01] [--gap-minutes 30]` — reads the main-session transcripts of this
  project (top-level `*.jsonl` only: background agents' transcripts live in subfolders and
  workflow worktrees are other projects, so they never count). Events = the timestamps of Ryan's
  own messages (type `user`, not `isMeta`, not a compaction summary, a text part not starting
  with `<` — task notifications and skill loads are excluded) and of assistant messages. All
  sessions merged (two open sessions never double-count), split by local calendar day, clustered
  where a gap exceeds 30 minutes; a block counts only if it contains at least one of Ryan's
  messages (time an agent works alone while Ryan is away is not billed). Day hours = sum of
  block durations, rounded to the nearest 0.25 (at least 0.25 when any block counts).
- The log: `worklog/worklog.csv`, columns `date, hours, blocks, description, source`
  (`blocks` like `05:46-07:12, 13:40-18:02`, local time; `source` = `auto` or `manual`).
  `update` rewrites only `auto` rows for days it can see in the transcripts; it keeps a row's
  description once written (curated text wins), fills an empty one from that day's git commit
  subjects, never touches `manual` rows, and never deletes a day whose transcripts have expired.
- `add --date --hours --description` — a `manual` row (calls, work in the sheet outside Claude).
- `export --month 2026-09 [--out invoice.csv] [--rate N]` — runs from the log only: one row per
  day (auto + manual hours summed; descriptions joined), `Date, Hours, Description[, Amount]`, and
  a total row. Opens in Sheets/Excel.

**Back-fill (September)**: `update --since 2026-09-01`, then client-facing descriptions per day
written by a small workflow (one agent per working day, each given only a digest of that day:
Ryan's prompts, Claude's summaries, commit subjects), 1-3 plain sentences each, no girls' or
mentors' names, no e-mail addresses; Ryan reviews them before any invoice.

**Keeping it current**
- CLAUDE.md (Commands + Conventions): at the end of every working session run
  `python3 tools/worklog.py update` and write or refresh that day's description (client-facing,
  no names); month end: `export --month`.
- `docs/RUNBOOK.md` "Work log and invoices"; `docs/ARCHITECTURE.md` tool row; memory note.
- Optional, with Ryan's OK: raise Claude Code's transcript retention (`cleanupPeriodDays`, user
  settings) to 90 days so a missed `update` can still be recovered; a Stop hook running
  `update` automatically would need `.claude/settings.json`, which the guardrail hook protects —
  snippet provided for Ryan to add himself if he wants it.
