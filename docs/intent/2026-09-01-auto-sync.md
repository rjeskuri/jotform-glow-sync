# Intent: automatic Jotform sync

## Problem

Since launch, a new club or a roster change submitted through the Google Form updates the
sheet's Roster tab within seconds, but the attendance forms only change when someone with the
Jotform key runs export → dry run → apply per region. Ryan is that someone. Changes wait, and
mentors of a new club cannot record attendance until they do.

## Proposed outcome

When the Roster changes, the affected regional forms are updated without anyone at a keyboard,
and the sheet itself shows when each update happened (Ryan asked for "a timestamp audit or
something in the sheet"). If a change is unusual, nothing is written and a human is told what
and why.

## Affected users and systems

Mentors (new clubs appear on the form the same day); Ryan (no manual loop; reads `SyncLog`
and `ATTENTION.md` instead); the Apps Script bound to the sheet (sends the notification); the
repository's GitHub Actions (runs the sync with the credentials as secrets); the four regional
Jotform forms (written to unattended); Salesforce (unchanged mapping).

## Constraints

- Reuse the proven `sync_attendance_form.py`; do not port it to Apps Script.
- Dry runs until Ryan has read a day of logs; a one-variable kill switch.
- A blast radius a human can review: bands on creates/updates, never a delete, never `--prune`.
- Girls' names must not appear in logs or workflow artifacts.
- Credentials only in GitHub Actions secrets of a private repository and in `.env` locally.

## Open questions

- Trigger: event-driven (Apps Script → `repository_dispatch`) with a daily backstop, chosen
  over polling from Ryan's laptop (runs when the Mac is off).
- Change record: a `SyncLog` tab written by the runner, plus an Audit row per notification; the
  Roster's date columns cannot show reactivations.
- Still open: whether "at least one girl ticked" should be required on the forms.
