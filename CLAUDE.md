# jotform-glow-sync — notes for Claude

Python 3.10 + Node 18 tooling that keeps Global G.L.O.W.'s Jotform attendance forms in step with
the master enrollment Google Sheet (the sheet's Roster tab is the source of truth; the forms
follow). The data is rosters of girls — minors. Forms and sheet are LIVE since 2026-09-01.
Roster changes reach Jotform automatically: sheet → `Dispatch.gs` → GitHub Actions →
`tools/auto_sync.py`. Procedures: `docs/RUNBOOK.md`. Design: `docs/ARCHITECTURE.md`.

## Commands
- Once per clone: `make venv` (with the ruff `make check` needs) and `make hooks` (pre-commit
  secret scan and ruff, the commit template).
- `make check` — everything, offline: the verify command (CI and the stop hook run it); healthy
  ends `CHECK PASSED`. Python tests: `make py` (unittest discover).
- `python3 tools/auto_sync.py` — the automatic loop as a dry run (writes nothing); healthy: every
  region `in-sync` (a disabled form's `skipped - form DISABLED`). Read-only form report and sync
  dry run: `.claude/skills/form-status/SKILL.md`, `.claude/skills/sync-preview/SKILL.md`.

## Conventions
- Dry run by default; `--apply` writes; back up before a live write (`backup_forms.py --form`),
  re-read and compare after; refuse rather than guess (`sys.exit("what to fix")`).
- `print()`, argparse, standard library only (the Sheets tools excepted). Shared code in `glow/`,
  tools in `tools/`; `sync_attendance_form.py` and the rollback pair stay at the root.
- Fictional names only in tests, fixtures and docs (`test/fixtures/make_fixture.py`); girls' names
  never in logs (`auto_sync.redact`), commits, or this file.
- A change with a live rollout keeps a plan in `docs/plans/` beside its ticket (Rollout, Rollback,
  Result; `status:` `proposed|accepted|in-progress|blocked|done|superseded`). A decision: a dated
  section at the end of `docs/DECISIONS.md`. BACKLOG items keep their numbers (updates are dated
  bullets); new work is a ticket. Review against `REVIEW.md`.
- Commits: subject ≤ 72 characters, `area: what changed`, blank line, a body that says why;
  trailers when they apply: `Plan: docs/plans/…`, `Backlog: N`, `Live: none | <what, when UTC,
  Ryan's go>` (`.gitmessage`), and the same trailers in the pull request's Summary: landing is a
  squash merge, so the PR text is what reaches `main`.
- Before `/harness:land`: `/land-checks` — the runner's next run, the privacy audit, and the
  worktree's `data/` and `backups/` (land deletes them; 2026-10-09: the only copies of 11 files).
- Work log (invoiced monthly; RUNBOOK "Work log and invoices"): `--drop-stale` / `--rewrite-old`
  only on Ryan's word; a home-folder session counts only if `--transcripts` names it.

## Things Claude gets wrong
1. Every live write needs Ryan's explicit go in this conversation: `--apply`, `--prune`,
   `--rehearse`, `clasp push`, the sync's GitHub switches (`gh variable|secret set`, `gh workflow
   run … apply=true`), Salesforce writes and deploys. `.claude/hooks/live_gate.sh` blocks them
   (`gh` and `sf` too) unless HE exported `GLOW_LIVE_OK=1` before launching; it is a seatbelt, not
   the go: it misses the connectors and a write through another program.
2. The API key comes from `.env` / the environment, never a command line (command lines land in
   `.claude/settings.local.json` and transcripts — that leaked a key once).
3. The sync rewrites ALL conditions on every run, so anything added to a form by hand is wiped:
   new form features (like the Club picker) are generated by `build_conditions`, never hand-made.
4. `--prune` deletes questions: fresh clones only; the refusal on forms with submissions is a feature.
5. Question 5 (Club Name) is what Salesforce reads. With the Club picker it is hidden and filled by
   a calculation — keep it that way; never re-point the mapping. Its value is the club's
   Salesforce Account name (plain, or `<club> - <partner>` when another partner's club has the
   name): never change it for an existing club without renaming the Account first (the sync
   refuses without `--q5-change-ok`; RUNBOOK "Club names two partners share").
6. Active roster rows with a blank region reach NO form and only `auto_sync.py` (ATTENTION) and the
   sheet's ReviewQueue say so. A partner whose clubs do not report through Jotform is marked `no`
   in the Partners tab's `jotform` column instead — its rosters are retired, kept hidden and off
   the Club picker (RUNBOOK "Clubs that do not use Jotform"); never a blank region.
7. In BOTH Python and `appsscript/`, checked by `test/gs_parity_test.py` — change both (list:
   docs/ARCHITECTURE.md "Constants that exist on both sides"). qids, form ids, `SESSION_OVERRIDES`:
   Python only. `glow/sync.py SHEET_ZONE` is the sheet's own zone, not `appsscript.json`'s `timeZone`.
8. `appsscript/Regions.gs` is hand-kept data (its "GENERATED" header is stale), protected by the
   edit hook; the sheet's Partners tab wins over it. `data/`, `backups/`, `credentials/` hold PII
   or secrets: never commit, quote or print their contents.
9. Jotform `POST /form/{id}/translations` REPLACES a language's dictionary: GET, merge, POST; a new
   English string also needs its `base`+`en` entries (`.claude/skills/jotform-api`).
10. Python `read_sheet` keeps partner-less rows and only strips `-` bullets; Apps Script drops those
    rows and strips `•`/`*` too — known divergences, do not silently fix one side.
11. Node 18 + clasp 2.4.2 are pinned. A new Google service in a `.gs` file adds an OAuth scope, and
    until the owner re-authorizes, the form-submit trigger FAILS HARD (`make gs` fails on a 9th
    service). Push, rollback and its floors: `.claude/skills/deploy-appsscript/SKILL.md`.
12. Salesforce: VPN off before any `sf` call (Salesforce freezes the user); the tools take `--vpn-off`.
    Writes only on Ryan's go, one record per call, never from a subagent.
    Access: `.claude/skills/salesforce/SKILL.md`.
